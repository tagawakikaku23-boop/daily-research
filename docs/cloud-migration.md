# PCを起動しない日報配信への移行

## 変更前

- 日報は2026-08-27にGitHub Actionsのscheduleを停止し、Windows予約へ移行。
- GitHub Actionsの日報最終成功は2026-08-27、実行 #203。
- 朝の失敗 #201 では欠損株価から整数変換したため停止していた。
- 従来は朝に株式、夜に株式とニュースを作成。
- 銘柄更新・月次レビューのクラウド予約は稼働しており、本変更では変更しない。

## 変更後

- 予約は日本時間7:00・19:00。朝夜それぞれ株式とニュースを作成。
- 既存の月曜7:30の週次レポートもPC停止後にクラウドへ移行する。
- GitHub Actionsは開始時刻の保証がなく、混雑時は遅延・実行漏れがあり得る。
  7時・19時は予約時刻であり、Notionへの掲載は収集・生成終了後。
- 定時投稿は cloud-reporting.json の enabled: true で有効。旧PCの3予約を本人が無効にしたことを2026-10-28に確認した。
- Repository variable CLOUD_REPORTS_ENABLED=false は緊急停止として優先。未設定なら設定ファイルに従う。
- 設定ファイルをmainに反映した際、activationの日付が日本時間の当日に一致する場合だけ、指定した朝/夜を検証する。投稿済みの同じ回はスキップする。
- 同一日の朝/夜/週次は既存Notionページを照会して再投稿を抑止。
  ニュースは朝と夜を分ける。明示的なmanualモードは従来どおり再生成する。
- Notion照会に失敗したら投稿せず停止。ページ作成POSTは結果不明時に再試行しない。
- 追加ブロックの失敗はジョブ失敗にする。新規ページは完成まで⏳アイコン、
  全ブロックの保存後に従来のアイコンに戻す。作成中ページが残る場合は再投稿せず停止。
- 旧PCが更新前コードで実行した場合、クラウドの同時実行制御や重複判定では競合を完全には防げない。
  必ず旧PCの予約を先に無効にする。過去の途中作成ページは自動修復・削除しない。
- 既存のNotionデータベース・プロパティ・過去ページは維持。
- 欠損終値を除外し、有効価格なしは銘柄単位の取得失敗として扱う。
- 前回シグナル・発掘履歴の保存は継続。投稿前のスナップショット更新はしない。
- 保有銘柄・株数・取得単価を公開Python/CSVから除去し、Notionのみから読み込む。
  読込失敗時の公開CSV・既定リストへのフォールバックを廃止する。
- 前回データはNotionの「配信の引継ぎデータ（自動更新）」へ保存。
  既存の公開スナップショットをここへ移し、以後GitHubへの書き戻しはしない。
- GitHub Actionsの日報・銘柄更新・月次レビューでは、個人情報を含み得る実行ログを公開しない。
- 現在の公開ファイルからの除去では、過去コミット・既存の実行ログは消えない。
  Git履歴全体の書き換えや過去ログの削除は本変更の対象外。

## 切替手順

1. 旧デスクトップで「タスク スケジューラ」を開く。
2. 「タスク スケジューラ ライブラリ」で以下を右クリックし「無効」を選ぶ。削除しない。
   - DailyResearch_Morning
   - DailyResearch_Evening
   - DailyResearch_Weekly
3. 「実行中」であれば終了を待ち、Notionに作成済みの同日レポートがないか確認する。
4. GitHubの「Report migration validation」のtestsとconnectionsが成功していることを確認。
   接続確認は秘密値・APIレスポンス本文を出力せず、Notionへの書き込みもしない。
5. Actions → 毎日リサーチ日報 → Run workflow。
   最初はmode=check、action=checkで実行。投稿を伴う検証は、未投稿の回で
   mode=morningまたはevening、action=postを選ぶ。投稿成功とNotion本文を確認する。
6. cloud-reporting.json の enabled を true にする。通常のコード更新では検証投稿は起動しない。
   activation は切替検証の日付・モードだけを指定する。別日には自動で検証を投稿しない。
7. 次の朝夜の実行とNotion掲載を確認する。GitHub Actionsの失敗通知も有効にする。

## 失敗と再実行

- 株式が完了・ニュースが失敗した場合、同じmorning/eveningで再実行すると株式をスキップしニュースを作る。
- 作成POSTのタイムアウト/5xxや⏳ページがある場合、先にNotionを確認する。
  既存内容を確認せず手動投稿・削除・アイコン変更をしない。
  ⏳を通常アイコンに戻すのは、本文の完成を確認した場合だけにする。
- 過去日の再実行には対応しない。モードは当日の日本時間の日付を使う。
- 設定済みの新聞ログインがクラウドで追加認証を要求する場合は別途対応が必要。
  読み取り接続確認では新聞ログインやAI生成、Notion書込権限までは確認しない。

## 戻す場合

先に cloud-reporting.json の enabled を false に変更するか、Repository variable CLOUD_REPORTS_ENABLED を false に変更する。GitHub側に実行中の日報がないことを確認。
その後、必要であれば旧PC側を有効にする。両方を同時に有効にしない。
Notionの過去記録や秘密値を削除する必要はない。
