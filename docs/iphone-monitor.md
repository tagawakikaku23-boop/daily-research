# Official iPhone research monitor

## Scope and evidence

An independent, append-only price-research workflow; no purchases, buyback applications, login, account cookies, card incentives or profit recommendations. Existing daily_report, refresh_watchlist, monthly_review and ops_health code/workflows are unchanged. Base main commit: f15562595fa07db116f75e26bbb9dd8f298ff0d3.

The public MobileMix HOME initially displays the featured (買取強化) table. A normal first-party browser session with cookies enabled rendered it on 2026-10-29. A stateless reader redirected to /cookie-error. No CAPTCHA handling, stealth, proxy rotation, cookie fabrication or restrictions bypass is used. Robots are checked (MobileMix returned 404); access denials and unknown robots responses stop collection. Terms are retrieved and hashed on each run. A detected automation-specific condition stops collection for review. This does not constitute a guarantee that future terms or markup will remain unchanged.

Parse only visible featured model/price/condition cells; never submit or click buyback forms. Apple official public product-selection data are matched by model, capacity, color and UNLOCKED_JP; JPY, tax text, non-refurbished condition and valid prices are checked. Parse no third-party prices. Previous third-party Notion records remain unchanged and distinct from new MM公式 records. Capacity/model targets currently cover the featured Duo and 18 Pro/Pro Max; other categories are out of scope. New/unknown featured iPhones without an exact Apple mapping are recorded as unacquired, requiring mapping review.

Color deductions come from the visible official note; ambiguous conditions produce null values. Buyback prices are after the color deduction; original featured base and publication date are retained in 備考. Gross difference is color-adjusted buyback minus same-variant Apple tax-inclusive retail. Shipping, other costs and net profit remain null. No confirmed color-specific Apple shipping quote was present in captured bootstrap data, so 納期 explicitly says 未取得. Generic "earliest tomorrow" banners and third-party delivery estimates are never copied as variant-specific delivery dates.

Give that integration access to the destination page if needed; a missing grant fails without modifying schema.

Branch push runs regression tests and a live read-only collection. Use workflow_dispatch with save=true for an explicit append validation, with immediate read-back of every field and a second save attempt proving no second row is created. The first branch integration attempt acquired 30/36 paired official prices but failed Notion preflight with 404; no page create was reached. Destination integration access must be granted before retrying the save test. A new official-source snapshot is intentionally distinct from any existing comparison-source snapshot. ## Activation and operation

The new schedule is JST 08:00 and 20:00. It remains gated by repository variable IPHONE_MONITOR_ENABLED == true, which defaults to disabled. A branch's cron does not run until merged to the default branch. Keep the gate off until the existing ChatGPT iPhone task is paused and live branch validation succeeds. Main merge and gate activation require a reviewed cutover; do not alter the existing news schedule. Delays beyond 12:00 for morning or midnight for evening stop, rather than label old observations with a new slot.

Stop: set IPHONE_MONITOR_ENABLED=false (or remove it). Manual workflow_dispatch defaults to read-only; the save input explicitly requests an append. Disable the workflow if necessary. Roll code back by reverting only this change; don't revert unrelated news fixes. Keep research records as history; any removal/correction requires user approval. The pre-existing scheduled reporter had a late-night dispatch rejected by its safe delivery window before this change; this monitor does not modify that behavior.

## Stable reader contract and target tracking

Every new observation page contains a JSON code block with schema_version=1 and record_kind=iphone_price_observation. Fields: record_key, slot, observed_at (offset-aware JST), source_kind=official, sources (buyback/Apple URLs and buyback publication date), row (model/capacity/color, prices, conditions, delivery, null costs/net), price_change and save_result. The prior observation must use the same official URL, exact model/capacity/color, an earlier observation time, official-confirmed quality, and a verified receipt. No comparisons against third-party, failed or unverified records. First observation or missing price means a null delta. Original observations are immutable; only their own new receipt is finalized after checking saved properties. Unknown create/patch outcomes are reconciled from the saved snapshot, without creating replacements or overwriting older research. A missing snapshot requires review.

The JSON save_result starts pending_readback; after verifying every saved property, update only that new observation's code block to verified with verified_at, then retrieve that block and compare its full JSON. Any error fails the run. The public Actions artifact contains public-source prices and generic write status, without Notion page IDs, API response bodies, integration names or credentials. Future GPT readers should select the newest verified snapshot for an exact variant, check freshness and per-field null values, and explicitly flag the latest failed acquisition rather than promoting yesterday's value to current. Third-party historical records remain separate. No GPT notification task is created by this PR.

iphone-monitor-targets.json lists model, Apple slug and capacities. Retrieve featured models first, then remaining tracked Apple pages; preserve tracked variants as unacquired when absent from the featured table. Adding an Apple model/slug/capacity is a configuration change; Notion select choices are validated first, never created automatically. Non-featured MobileMix category acquisition is a future adapter, not implemented or claimed as covered.

## Cost and release gate

No LLM API is called by this monitor. Two daily runs at about 3–7 minutes each after the receipt checks mean an estimated 180–420 runner minutes/month; this is an estimate, not measured production use. Standard GitHub-hosted runners in this public repository have free compute under the current official policy. Artifacts have separate storage allowances; keep only the small public JSON for seven days (roughly under 1 MB active evidence at this scale, excluding platform overhead). No paid runner is configured. See https://docs.github.com/en/billing/concepts/product-billing/github-actions .

At 36 color observations per run, two runs/day add approximately 2,160 Notion pages and code blocks/month. Workspace block/page/API/automation plan limits still apply; the user's plan and billing have not been audited. API calls are serialized at a minimum 0.35-second spacing. HTTP errors stop safely and are surfaced; they are not bypassed. See https://developers.notion.com/reference/request-limits . Future GPT notification tasks would have separate ChatGPT plan/usage costs, outside this monitor.

Before enabling the production schedule, report actual cloud acquisition/save/dedup tests, unchanged existing file comparison, runtime and expected costs to the user, and obtain explicit approval. Keep the PR unmerged and IPHONE_MONITOR_ENABLED unset/false until that approval and the prior ChatGPT writer's pause are confirmed. Do not interpret approval to connect Notion as approval to enable the schedule.
