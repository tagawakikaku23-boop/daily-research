# 投資HOME Ver.1.0 検証版

## 状態

専用ブランチの実装候補。本番自動更新・HOME切替は未承認で無効。
本番Notionスキーマは未変更。検証ページと検証専用DBだけを新規作成した。

## 変更

- `investment_analysis.py`：副作用のない通貨換算、配当、損益、鮮度、候補条件、業種分散、JST週キー、欠損を明示する集計。
- `investment_home.py`：架空データのHOME表示・検証ページ限定の週次保存。通常は書込みなし。実データ入力はまだ接続しない。
- `daily_report.py`：未調整終値を使用し、一株年間配当から百分率を算出。未確認の為替や不完全な保有配当集計では停止。ニュースの対象企業を照合。財務根拠のない既存の買い判定は判断保留へ変更。52週値の欠損を表示上の正常値にしない。
- `monthly_review.py`：不完全な株評価・投信入力・為替では履歴保存を停止。全行の評価後に積立口数を更新する。未検証の推計誤差表記を削除。
- `refresh_watchlist.py`：未確認の52週位置と配当は数値列へnullを書き込む。本番には未適用。
- `.github/workflows/investment_home.yml`：手動起動のみ。架空データだけを処理。検証ページ以外の保存先をコードで拒否し、同時実行を直列化。
- `tests/test_investment.py`：金融計算、ニュース照合、欠損・異常値、月次の変更前検証、重複防止、部分成功のテスト。

## 安全性と仕様

価格通貨と配当通貨を区別する。為替は正の有限値のみ。新HOMEでは為替7日、価格7日、財務/配当400日を検証上の上限とし、未来日時と時差不明日時を拒否する。期限はデータ更新頻度を確認して本番前に再評価する。

候補の暫定条件は、希望利回り達成、配当性向0超70%以下、利益/営業CF/FCFが正、5年減配なし、業種枠内、購入上限以下。基準未確認は候補にしない。TOP3は同一業種を重複させず、該当数だけ表示する。実際の売買判断や注文ではない。

一株年間配当 `dividendRate` の期間・通貨・特別配当の扱いは一次資料と照合する必要がある。価格と年間配当から利回りを算出し、単位不明の `dividendYield` を推測変換しない。30%超の利回りは確認対象として欠損扱いにする。価格は配当調整を避けるため `auto_adjust=False` を明示する。

yfinanceの公式案内は調査・教育用途およびYahooデータの個人利用を説明している。取得データを公開ページやリポジトリへ複製しない。利用権の最終確認は本番適用前に行う。
参考：https://ranaroussi.github.io/yfinance/ 、https://github.com/ranaroussi/yfinance

既存の公開ログ抑止とNotion配信重複防止は維持。新処理は例外詳細を公開しない。POSTタイムアウトを自動再試行せず、次回は同じ年週のページを確認する。Notionに一意制約がないため、Actions外からの同時投稿まで厳密に一意性を保証するものではない。

## 本番前に残ること

1. 実データ入力アダプターと本人目標の接続。本番監視DBへの列追加の確定差分を提示した後に適用する。
2. 企業別名の確認、記事掲載日時とURL重複排除の追加。見出しの企業一致だけでは子会社・同名・否定表現を完全には判別できない。
3. 既存取得単価が円建てである仕様の実データ確認。新HOMEの関数は通貨を指定できるが、旧レポートは既存の円建て仕様を継承する。
4. 配当期間・特別配当・分割調整の出典照合、ETF/REIT/金融業の専用基準。本番の財務情報充足率は未検証。
5. 新処理の実API経路での結合試験、429/障害時の待機方針、PC/スマホ表示の目視確認。
6. 新週次処理から判断/学習DBへの自動保存を接続。現在はログDBと架空例、週次本文まで。
7. 月次予約のJST月初への修正、同時実行対策、推定基準価額と実残高の確認。今回は既存の予約設定を変更していない。
8. 既存レポートの本番相当データでの回帰。不完全な金融データでは新ブランチの株レポートが停止する挙動は意図した安全策だが、欠損を含むレポート表示を継続する設計への改善余地がある。朝夕ニュースの生成は株レポート失敗時にも試みることを追加テストで確認した。

## 切替・復旧

検証結果と未解決点が解消するまでmerge・本番有効化はしない。承認後に追加スキーマのみを適用し、読取りdry-run→単発保存→読戻し確認→HOME入口変更→週次予約有効化の順とする。旧HOMEとログを保持する。

復旧時は新HOMEの更新だけを停止し、入口を旧HOMEへ戻す。既存日報のスイッチは変更しない。コードは対象コミットだけをrevert。追加DB/プロパティ/履歴は削除せず保持し、必要な訂正は対象を明示して行う。
